# 변경 검토

1. `git diff`로 범위를 확인하고 `docs/spec/gap-analysis.md`의 해당 단계·요구사항 번호와 비교한다. 범위 밖 변경은 분리하거나 이유를 적는다.
2. 역할을 지정받은 작업이면 `docs/AI_AGENT_HARNESS.md` 역할 소유 표의 쓰기 범위 안인지 확인한다.
3. 이 저장소가 조용히 틀리는 경계를 본다: 좌표 off-by-one·역방향 범위, transaction 누락, undo origin(남의 변경까지 되돌림), awareness 정리, 상태 공급원 중복(`Y.Doc`과 Zustand), AI 취소·실패 전파, 생성 중 대상 변경, 요청 본문·모델 출력의 범위 검증, 키 노출.
4. 재현 가능한 결함은 위치·영향·재현 조건으로 보고한다. 취향은 결함과 구분한다.
5. 바뀐 사실의 소유 문서와 `last_verified`가 갱신됐는지, LLM 제안을 기각·수정했으면 `LLM_REPORT.md`에 기록됐는지 확인한다.
6. 보고한 검증이 실제 실행 결과와 일치하는지 본다. 가짜 응답·단일 탭 확인을 실제 AI·다중 탭 확인으로 보고하지 않는다. `pnpm check` 통과를 의미적 검토 완료로 보지 않는다.
