# 요구사항 수령

1. 원문은 고치지 않는다. 공유 가능 여부가 불분명한 원문은 커밋하지 않고 사용자에게 확인한다.
2. `docs/spec/requirements.md`에 영역 접두사(E 시트 편집, C 공동 편집, A AI 편집, X 공동 편집 × AI, T 기술 조건, D 배포·문서 조건)와 번호를 붙여 한 줄씩 옮긴다. 원문의 뜻을 바꾸거나 요구를 합치거나 빼지 않는다.
3. 모호한 항목은 해석과 근거를 해당 번호 옆에 적고, 결과가 크게 달라지는 해석은 사용자에게 확인한다. "스스로 정하라"는 항목(X1~X3 같은 정책)은 선택과 이유를 `DESIGN.md`와 README 결정 절에 둔다.
4. `docs/spec/gap-analysis.md` 백로그를 동작하는 상태로 끝나는 단계(M1, M2…)로 나누고 각 단계에 요구사항 번호를 붙인다. 기술 조건은 `TECH_RULES.md`로 옮긴다.
5. 개정본이면 바뀐 번호만 갱신하고, 이미 완료한 단계 중 영향받는 것을 백로그에 재확인 행으로 추가한다. 번호를 재사용하지 않는다.
