# 역할 분해와 병렬 실행

사용자 또는 주 세션이 병합 담당으로 적용한다. 역할 에이전트(`.codex/agents/sheet-<역할>.md`)는 자기 작업만 하고 다른 역할을 다시 호출하지 않는다.

1. 분해: 요청을 역할별 작업으로 나눈다. 각 작업에 역할·목표·근거 요구사항 번호·쓰기 범위·선행 작업·완료 조건·검증 명령을 적는다. 쓰기 범위는 `docs/AI_AGENT_HARNESS.md` 역할 소유 표를 넘지 않는다.
2. 실행 방식 선택: 기본은 한 세션에서 역할 관점만 바꿔 순서대로 진행한다. 병렬은 다른 역할이 기대는 결정(요구 해석, core 공개 API, 문서 스키마)이 확정되고 쓰기 범위가 겹치지 않는 작업이 둘 이상일 때만 쓴다. 디자인과 프론트는 같은 컴포넌트 파일을 쓰므로 순서대로 진행한다.
3. 격리: 병렬 쓰기 작업마다 별도 git worktree와 `<역할>/<주제>` 브랜치를 쓴다. 저장소를 수정하지 않는 역할은 worktree 없이 실행한다. 작업 지시는 기록 파일로 남기지 않고 실행 도구에 직접 전달한다.
4. 인계: 각 역할은 역할·변경·검증·미검증·다른 역할에 넘길 요청·남은 사람 결정 형식으로 종료 보고한다. 넘길 요청은 다음 분해의 입력이 된다.
5. 병합: 선행 작업부터 병합하고 병합마다 `README.md` 검증 절의 명령을 실행한다. 충돌은 해당 경로의 소유 역할 기준으로 해결한다. 병합 후 `change-review`를 적용하고 `backlog` 절차로 상태를 갱신한다. 커밋은 `git-commit` 규칙(작성 주체 태그)을 따른다.
6. 보고: 역할별 결과, 실행한 검증, 미검증, 남은 사람 결정을 합쳐 보고한다. 한 역할의 실패를 다른 역할의 성공으로 덮지 않는다.

실행 예: Claude Code는 Agent 도구에 `subagent_type: sheet-<역할>`, `isolation: worktree`로 작업을 한 메시지에 함께 보낸다. Codex 등은 worktree별 세션에서 `.codex/agents/sheet-<역할>.md`를 읽고 작업하도록 지시한다.
