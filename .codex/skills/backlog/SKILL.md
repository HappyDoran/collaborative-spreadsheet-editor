# 백로그 갱신

`docs/spec/gap-analysis.md`가 다음 작업을 정한다. 요구사항 번호는 `docs/spec/requirements.md`, 확정된 설계 판단은 `DESIGN.md`가 소유한다.

1. 착수: 백로그 표에서 가장 앞선 미완료 단계를 고른다. 앞 단계를 건너뛰려면 이유를 사용자에게 확인한다. 막는 미결 결정이 있으면 착수하지 않고 결정을 요청한다.
2. 범위: 해당 단계의 요구사항 번호만 구현한다. 범위 밖 개선은 백로그에 새 행으로 남긴다.
3. 완료: `test-policy` 완료 조건의 검증을 실행한 뒤 상태를 `완료 (검증 근거)`로 바꾼다 — 예: `완료 (E2E 12건 + Safari·Chrome 수동 확인)`. 판정 요약의 날짜와 자동 테스트 건수를 함께 갱신한다. 브라우저 확인이 남았으면 `구현 완료·수동 미확인`으로 둔다.
4. 결정: 사람이 결정하면 근거를 `DESIGN.md` 절로, 규약이면 `TECH_RULES.md`로 옮기고 gap-analysis에서 지운다. 요구 해석이 바뀌면 `docs/spec/requirements.md`도 고친다.
5. 하지 않기로 한 항목은 지우지 않고 이유와 결정자를 판정 요약의 "하지 않은 리뷰 항목"에 남긴다.
