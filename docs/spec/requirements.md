# 요구사항 요약

이 문서는 요구사항 번호의 정본이다. 구현 상태와 우선순위는 `docs/spec/gap-analysis.md`가, 설계 근거는 `DESIGN.md`가 소유한다. 요구사항 해석이 바뀌면 이 문서를 갱신한다.

구현 원칙: 기능 개수보다 요구사항을 꼼꼼하게, 사용자 입장에서 감각 있게 구현한다. 적은 기능을 완성도 있게 만드는 쪽을 택한다. 코드는 이해·설명 가능하고, 중복·복잡도가 정리되어 있고, 기술 선택 이유를 설명할 수 있어야 한다.

## 기술 조건

- T1 TypeScript, Next.js, React
- T2 동기화 라이브러리(Yjs, Automerge 등) 사용 가능. CRDT/OT 직접 구현 불필요
- T3 같은 브라우저의 각 탭 = 서로 다른 참여자. 탭 간 동기화는 BroadcastChannel·storage 이벤트·IndexedDB 등 브라우저 API만으로. 다른 브라우저·시크릿 창·다른 기기 동기화는 요구하지 않음
- T4 네트워크 기반 동기화로 확장할 때 바꿔야 할 것을 README에 기술 (구현 불필요)
- T5 실제 LLM 연결. 사용 한도를 설정할 수 있는 API 키, 소액 충전. Provider·모델 자유
- T6 AI 응답 지연·스트리밍·실패 처리

## 기능 요구사항

### E. 시트 편집
- E1 셀 선택(단일, 범위)과 값 입력·수정
- E2 방향키·Enter·Tab 등 키보드로 셀 이동
- E3 굵게·기울임 등 기본 서식, 주요 서식은 키보드 단축키로도 적용
- E4 실행 취소 / 다시 실행
- E5 새로고침하거나 모든 탭을 닫았다 다시 열어도 내용 유지

### C. 공동 편집
- C1 새 탭에서 같은 시트를 열면 새 참여자로 합류하고 그 시점 내용이 바로 보임
- C2 여러 탭에서 동시 편집, 변경 실시간 반영
- C3 동시 편집에도 상태가 충돌하거나 깨지지 않는 안정적 동기화
- C4 참여자는 이름과 색으로 구분, 현재 접속 중인 참여자 목록 확인
- C5 다른 참여자가 선택한 셀·범위와 현재 편집 중인 셀이 보임
- C6 탭을 닫은 참여자는 참여자 목록과 시트에서 사라짐
- C7 실행 취소는 내가 한 변경만 되돌림

### A. AI 편집
- A1 AI가 현재 시트 내용을 컨텍스트로 참조, 채팅 지시로 시트 내용이 실제로 변경됨
- A2 셀 범위를 선택해 AI에게 편집 요청
- A3 AI 결과는 바로 덮어쓰지 않음. 원래 값과 비교해 확인한 뒤 적용하거나 버림
- A4 결과 생성 과정이 실시간으로 보이고, 생성 도중 취소 가능
- A5 적용한 AI 편집은 한 번의 실행 취소로 되돌림

### X. 공동 편집 × AI (동작을 스스로 정하고 구현, 이유를 README에)
- X1 AI가 결과를 만드는 동안 다른 참여자가 대상 셀·범위를 수정하거나 삭제하면?
- X2 한 사람이 AI 결과를 검토하는 동안 다른 참여자에게 무엇이 보여야 하나?
- X3 두 사람이 겹치는 범위에 동시에 AI 편집을 요청하면?

## 배포·문서 조건

- D1 배포 링크 — 회원가입·로그인 없이 접근. 비개발자 포함 3~4명이 직접 사용
- D2 배포물에 이름·이메일·사진 등 개인정보 없음
- D3 README 필수 내용: 로컬 실행 방법(배포본과 동일 결과), 네트워크 동기화 확장 시 바뀔 부분(T4), 주요 의사결정과 이유(X1~X3 포함)
- D4 `LLM_REPORT.md` — 도구·사용 방식·에이전트 컨텍스트, 파일 단위 역할 구분, LLM 기각·수정 사례, 핵심 프롬프트 (저장소 자체 기준)
