# 요구사항 대비 갭 분석과 보완 백로그

요구사항 번호는 `docs/spec/requirements.md`가 소유한다. 이 문서는 "지금 어디까지 왔고 다음에 무엇을 하는가"만 적는다. 항목을 끝내면 상태를 바꾸고, 확정된 결정은 `DESIGN.md`로 옮긴 뒤 여기서 지운다.

## 1. 판정 요약 (2026-10-03)

- 완료: 저장소 골격, Agent 작업 지원 체계, M1 단일 탭 편집(Safari·Chrome 수동 확인 완료), M2 공동 편집(C1~C7 + 참여자 이름 지정·수정·삭제) — 이름은 탭 단위(2026-10-03 개정).
- 자동 테스트: core 단위 테스트 53건(`pnpm test`), Playwright E2E 58건(`pnpm e2e` — 편집 12, 공동 편집 13, AI 18, 우클릭 메뉴 10, 공동 편집 × AI 5).
- 완료: M3 AI 편집(A1~A5, T5·T6) — OpenAI 직접 연결, 셀 단위 스트리밍, 시트 위 미리보기·적용·버리기, 가짜 응답 모드, 모델 선택. 실제 브라우저 수동 확인 완료(M3-3·5·7·8·11·12·14·15·17·19·20). 남은 수동 항목은 배포 후 M3-16.
- 완료: M3.5 우클릭 메뉴.
- 완료: M4 공동 편집 × AI(X1 바뀐 칸 건너뛰고 적용·요청 순간 기준, X2 상태만 공유, X3 겹침 경고) — 결정 근거는 `DESIGN.md` 15절, README 결정 절 작성.
- 완료: 배포 전 전체 코드 리뷰 — 결함 9건 수정·1건 한계 문서화, 중복 정리 (`LLM_REPORT.md` 사례 17).
- 완료: M5 배포(Vercel `collab-sheet-gamma.vercel.app`, CLI 배포, 키는 운영 환경 변수), README 필수 절(배포, 주요 의사결정, T4 네트워크 확장), 배포물 개인정보 점검, LLM_REPORT 프롬프트 발췌.
- 완료: 배포 후 관점별 리뷰(기획·디자인·개발) 반영 — 빈 칸 동시 편집·실행 취소 손실과 편집 중 원격 값 덮어쓰기 수정, 새 탭 안내, 제안 비교 가독성, 이름 제안, 대화 맥락, 예시 지시, 이름표 접기, 코드 분리(`fix/review-p0` 브랜치).
- 남은 일: 브랜치 병합·재배포, 제출용 zip(`git archive`). 하지 않은 리뷰 항목: 좁은 화면에서 AI 패널이 검토 칸을 덮음(평가는 데스크톱 중심), 다크 모드, 이름 상자 주소 이동.

M1~M3은 각 단계가 끝날 때 동작하는 상태로 커밋한다. 시간이 부족하면 M4의 표시 품질보다 M1~M3의 완성도를 먼저 지킨다 — 구현 원칙이 "적은 기능을 완성도 있게"다.
