# 요구사항 대비 갭 분석과 보완 백로그

요구사항 번호는 `docs/spec/requirements.md`가 소유한다. 이 문서는 "지금 어디까지 왔고 다음에 무엇을 하는가"만 적는다. 항목을 끝내면 상태를 바꾸고, 확정된 결정은 `DESIGN.md`로 옮긴 뒤 여기서 지운다.

## 1. 판정 요약 (2026-10-03)

- 완료: 저장소 골격, Agent 작업 지원 체계, M1 단일 탭 편집(Safari·Chrome 수동 확인 완료), M2 공동 편집(C1~C7 + 참여자 이름 지정·수정·삭제) — 이름은 탭 단위(2026-10-03 개정).
- 자동 테스트: Playwright E2E 24건(`pnpm e2e`) — 수동 매트릭스 10항목 초과로 test-policy 확장 조건 충족.
- 완료: M3 AI 편집(A1~A5, T5·T6) — OpenAI 직접 연결, 셀 단위 스트리밍, 시트 위 미리보기·적용·버리기, 가짜 응답 모드, 모델 선택. 실제 브라우저 수동 확인 완료(M3-3·5·7·8·11·12·14·17·19·20). 남은 수동 항목은 M3-15, 배포 후 M3-16.
- 미착수: X 전 항목(M4), 배포, README 필수 절(T4, X1~X3 결정 이유).

## 2. 미결 결정 (착수 전에 정한다)

| 결정 | 선택지 | 막는 항목 | 정할 시점 |
| --- | --- | --- | --- |
| X1 생성 중 대상 변경 | 제안 무효화 / 충돌 표시 후 사용자 선택 / 최신 값 위에 재계산 | X1 | M4 |
| X2 검토 중 다른 참여자 표시 | 범위 오버레이 + 상태 배지 / 표시 없음 | X2 | M4 |
| X3 겹치는 동시 요청 | 선점 잠금 / 둘 다 허용 후 적용 시 충돌 판정 | X3 | M4 |

## 3. 백로그 (우선순위 순)

| 단계 | 내용 | 요구사항 | 상태 |
| --- | --- | --- | --- |
| M1 단일 탭 편집 | 문서 스키마·연산, 그리드, 선택·입력, 키보드 이동, 서식+단축키, 복사·잘라내기·붙여넣기, undo/redo, IndexedDB 영속 (엑셀 조작 관례 — `DESIGN.md` 7절) | E1~E5 | 완료 (Safari·Chrome 수동 확인) |
| M2 공동 편집 | 탭 간 동기화, 참여자 목록·색, 원격 선택·편집 셀 표시, 탭 종료 정리, 내 변경만 undo, 이름 지정·수정·삭제 (`DESIGN.md` 11·12절) | C1~C7 | 완료 (E2E 16건 + 수동 확인 2026-10-03) |
| M3 AI 편집 | 서버 라우트, 스트리밍·취소·실패, 범위 선택 요청, diff 검토·적용·버리기, 한 번 undo (`DESIGN.md` 13절) | A1~A5, T5·T6 | 완료 (E2E 13건 + 수동 일부, 남은 수동 항목은 manual-scenarios M3) |
| M4 공동 편집 × AI | X1~X3 정책 구현과 README 결정 이유. X2 기반(생성·검토 범위를 awareness로 공유)과 X1 표시(원래 값 바뀜)는 M3 D안에서 구현 | X1~X3 | 일부 (정책 결정·README 남음) |
| M5 배포 | 배포, README 필수 절(T4 포함), `LLM_REPORT.md` 정리, 개인정보 점검 | D1~D4 | 미착수 |

M1~M3은 각 단계가 끝날 때 동작하는 상태로 커밋한다. 시간이 부족하면 M4의 표시 품질보다 M1~M3의 완성도를 먼저 지킨다 — 구현 원칙이 "적은 기능을 완성도 있게"다.
