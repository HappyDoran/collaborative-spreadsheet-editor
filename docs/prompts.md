# 프롬프트 기록

재사용할 프롬프트와 결과가 기대와 크게 달랐던 프롬프트를 발생 시점에 적는다. `LLM_REPORT.md` 4절은 여기서 2~3개를 골라 옮긴다. 원문이 길면 요지만 적고, 개인정보와 비밀은 적지 않는다.

형식: 날짜 · 단계 · 프롬프트 요지 · 결과 · 판정(잘 됨 / 실패 / 보완) · 이유.

## P1 — 골격과 Agent 작업 지원 체계를 먼저 세우기 (2026-10-02, 착수)

- **프롬프트 요지**: "골격부터 만들되, 기능 구현 전에 Agent 작업 지원 체계를 정해진 순서로 세운다 — 도구 중립 라우터 문서, 사실 하나당 소유 문서, 작업 유형별 skill, 구조 검사 스크립트, LLM 기록 문서. Node(mise)·Next·React 버전을 고정한다."
- **결과**: 골격 커밋 2개(workspace·Next 앱, core 주소 규약 + 테스트) 뒤에 `AGENTS.md`·`TECH_RULES.md`·`DESIGN.md`·skill 3종·`scripts/check-structure.sh` 생성.
- **판정**: 잘 됨.
- **이유**: "무엇을 만들지"보다 "어떤 순서와 경계로 만들지"를 지정해, Agent가 기능 코드보다 규약(상태 소유권, origin 기반 undo, AI 결과 비기록)을 먼저 문서로 고정했다. 이후 세션은 이 규약에서 시작한다.

## P2 — 팀 기술 스택 기준으로 스택 확정 (2026-10-02, 착수)

- **프롬프트 요지**: 목표 기술 스택(TypeScript·Next.js·React, Zustand, pnpm monorepo, Vitest, styled-components, Yjs)을 붙이고 골격에 반영하도록 지시.
- **결과**: pnpm workspace(`apps/web` + `packages/sheet-core`), Vitest를 core에, Zustand·styled-components·Yjs는 첫 사용 커밋에서 추가하도록 `TECH_RULES.md`에 고정. TanStack Query는 캐시할 서버 데이터가 없어 미채택으로 근거와 재검토 조건을 `DESIGN.md`에 기록.
- **판정**: 보완 — 스택 목록을 그대로 다 설치하지 않고, 쓰는 시점에 넣는 규칙과 미채택 근거로 바꿨다.
- **이유**: 목록을 미리 설치하면 쓰지 않는 의존성이 생기고, "왜 썼나"에 답할 수 없는 코드가 된다.

## P3 — 익숙한 도구를 UX 기준으로 삼기 (2026-10-02, M1)

- **프롬프트 요지**: "M1 방식은 엑셀을 다루는 것과 같은 맥락이다. 사용자가 가장 많이 쓰는 표는 엑셀이니 엑셀 UI/UX와 비슷하게 가져간다." 이어서 "복사·붙여넣기는 많이 쓰는 작업이므로 포함하고 그 이후 M1 진행" (frontend-design skill로 실행).
- **결과**: 키맵·모드(준비·입력·편집)·상태 표시줄까지 엑셀 관례를 표로 고정한 뒤 구현. 결정 문서 → core 연산·테스트 → UI 순서로 진행했고, 브라우저 시나리오 21건으로 검증.
- **판정**: 잘 됨.
- **이유**: "엑셀처럼"이라는 기준 하나가 수십 개의 세부 동작(Tab 후 Enter, Delete는 서식 유지, 단일 셀 붙여넣기 채우기)을 판단 없이 정하게 해 줬다. 범위 밖(수식·채우기 핸들)도 같은 기준으로 명시적으로 잘랐다.

## P4 — 기능 요구를 번호 목록으로 구체화 (2026-10-03, M2)

- **프롬프트 요지**: 참여자 이름 흐름을 번호 목록으로 지시 — 첫 접속 때 이름 지정, `localStorage` 같은 반영구 저장, 헤더 오른쪽 이름 UI로 CRUD, 이름 첫 글자 원형 아바타의 배경색 = 셀 포커스 색, 10색을 골라 무작위 지정, 전송은 추천대로 BroadcastChannel. 이어서 "1번 작업 후 자동 테스트 도입".
- **결과**: 결정 문서(`DESIGN.md` 11·12절) → core 순수 로직(팔레트·색 고르기·이름 정규화·동명이인 번호) + 테스트 → collab provider → hooks·UI 순으로 구현. 두·세 탭 시나리오 22건 통과.
- **판정**: 잘 됨, 보완 1건.
- **이유**: 화면·저장 위치·색 규칙까지 정해 준 목록이라 해석 여지가 적었다. 다만 목록끼리 또는 명세와의 충돌(공유 저장소 vs 탭별 참여자)은 목록 안에서 드러나지 않아, 구현 전에 짚고 보완 방식을 문서로 남겼다 (`LLM_REPORT.md` 사례 7).

## P5 — 충돌 보고에 대한 개정 지시 (2026-10-03, M2)

- **프롬프트 요지**: "localStorage 지시와 명세의 충돌을 막는 방법을 추천해 진행. 새로고침해도 이름은 유지. DESIGN.md에 적힌 대로 sessionStorage 사용, 단 이름 중복은 허용. 남은 일은 수정 후 다시 정리."
- **결과**: 이름·색을 탭 단위 `sessionStorage`로, `localStorage`는 새 탭 기본값으로만. 같은 이름 허용에 따라 번호 붙이기와 탭 간 이름 동기화 코드를 삭제. 새 E2E(`M2-N3`)가 새로고침 구독 누락 결함을 잡음(`LLM_REPORT.md` 사례 8).
- **판정**: 잘 됨.
- **이유**: 앞선 완료 보고에 충돌과 전환 경로를 미리 적어 둔 덕에, 지시가 "그 경로대로 + 두 가지 조건"으로 짧고 정확해졌다. 조건 하나(중복 허용)가 보완 코드 전체를 불필요하게 만들어 코드가 줄었다.
