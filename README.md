# Collaborative Sheet

여러 브라우저 탭에서 같은 시트를 동시에 편집하고, AI에게 범위 편집을 제안받아 검토 후 적용하는 웹 스프레드시트.

- 상태: 편집(M1)·공동 편집(M2)·AI 편집(M3) 구현. 진행 상황은 `docs/spec/gap-analysis.md`.
- 구조: pnpm workspace — 도메인 로직 `packages/sheet-core`, Next.js 앱 `apps/web`. 상세는 `docs/architecture/folder-structure.md`.

## 로컬 실행

필요 도구: [mise](https://mise.jdx.dev) (Node·pnpm 버전 관리).

```bash
mise install            # mise.toml의 node 24.18.1, pnpm 10.34.6 설치
node -v                 # v24.18.1 확인 — 다른 Node가 PATH 앞에 있으면 mise 버전이 가려진다
pnpm install
cp apps/web/.env.example apps/web/.env.local   # OPENAI_API_KEY 채우기 (AI 편집용)
pnpm dev                # http://localhost:3000
```

AI 편집: 키는 서버에서만 읽는다(`apps/web/src/app/api/ai/route.ts`). 개발 서버는 **가짜 응답 모드**로 시작한다 — 왼쪽 위 버튼으로 실제 AI와 바꿀 수 있고, 배포본에서는 주소에 `?debug=1`을 붙였을 때만 그 버튼이 보인다. 키가 없어도 가짜 응답으로 전체 흐름을 볼 수 있다.

공동 편집 확인: 같은 브라우저에서 같은 주소를 탭 여러 개로 연다. `localhost`와 `127.0.0.1`은 서로 다른 origin이라 동기화되지 않는다.

## 공동 편집과 AI가 만나는 지점: 결정과 이유

원칙 하나로 정했다: **사람에게 알리고, 사람의 최신 편집을 지킨다.** AI는 보조 도구이고, AI가 결과를 만드는 사이 사람이 직접 바꾼 값이 더 최신의 판단이다. 상세 근거와 검토한 대안은 `DESIGN.md` 13·15절.

**AI가 결과를 만드는 동안 다른 참여자가 대상 셀을 수정하거나 삭제하면?**
결과를 버리지 않고, 그 칸만 "원래 값이 바뀜"(빨간 테두리·!)으로 표시한다. 적용 버튼은 [바뀐 n칸 빼고 적용]이 되어 그 칸을 건너뛰고, 나머지만 반영한다. "원래 값"은 요청을 보낸 순간의 값이다 — AI는 그 값을 보고 계산했으므로, 요청 뒤에 바뀐 칸에 AI 값을 덮으면 다른 사람의 편집을 지우거나 낡은 값으로 계산한 결과가 들어간다. 모든 칸이 바뀌었으면 적용 버튼을 잠그고 다시 요청하게 한다.
- 고르지 않은 안: 확인 후 덮어쓰기(남의 최신 편집을 지울 수 있다), 결과 전체 무효화(한 칸 때문에 전부를 잃는다).

**한 사람이 AI 결과를 검토하는 동안 다른 참여자에게는 무엇이 보여야 하나?**
누가 어느 범위를 AI로 만들거나 검토 중인지만 보인다 — 요청한 사람 색의 점선 범위, "서연 · AI 검토 중" 이름표, 참여자 목록의 상태. 제안 값은 보이지 않는다. 아직 적용 여부가 정해지지 않은 값이 다른 사람 화면에 보이면 확정된 값으로 오해할 수 있기 때문이다. 제안은 요청한 사람 탭의 초안(새로고침해도 남고 탭을 닫으면 사라짐)이고, 시트에는 적용된 값만 들어간다. 다른 참여자는 그 범위를 계속 편집할 수 있고, 그 편집은 위의 규칙으로 보호된다.

**두 사람이 겹치는 범위에 동시에 AI 편집을 요청하면?**
막지 않고 알린다. 보내기 전에 내 대상이 다른 사람의 AI 작업 범위와 겹치면 "서연님이 A2:A3 범위를 AI로 검토하는 중이에요. 겹치는 칸은 먼저 적용한 쪽이 반영돼요."를 보인다. 둘 다 진행할 수 있고, 먼저 적용한 결과는 나중 사람에게 "원래 값이 바뀜"이 되어 건너뛰어진다 — 충돌 처리는 첫 번째 규칙 한 곳에 모인다.
- 고르지 않은 안: 선점 잠금. 탭끼리 주고받는 상태로는 같은 순간에 보낸 두 요청을 막을 수 없고, 탭이 죽으면 잠금이 최대 30초 남으며, 누군가 시트 전체로 요청하면 모두가 막힌다. 불완전한 잠금은 "막힌 줄 알았는데 겹친" 더 헷갈리는 상황을 만든다.
