# Collaborative Sheet

여러 브라우저 탭에서 같은 시트를 동시에 편집하고, AI에게 범위 편집을 제안받아 검토 후 적용하는 웹 스프레드시트.

- 상태: 편집(M1)·공동 편집(M2)·AI 편집(M3)·우클릭 메뉴(M3.5)·공동 편집 × AI(M4) 구현. 진행 상황은 `docs/spec/gap-analysis.md`.
- 구조: pnpm workspace — 도메인 로직 `packages/sheet-core`, Next.js 앱 `apps/web`. 상세는 `docs/architecture/folder-structure.md`.

## 배포

https://collab-sheet-gamma.vercel.app — 가입·로그인 없이 바로 쓴다 (Vercel, 실제 AI 연결).

- 공동 편집: 같은 브라우저에서 이 주소를 탭 여러 개로 연다. 탭마다 이름을 정하면 서로 다른 참여자가 된다.
- AI 편집: 범위를 고르고 툴바의 AI 편집 버튼(⌘K / Ctrl+K, 또는 우클릭 → AI로 편집…)으로 지시한다. 제안은 시트 위에 원래 값과 함께 보이고, [적용]해야 시트가 바뀐다.
- 가짜 응답 전환 버튼은 주소에 `?debug=1`을 붙였을 때만 보인다.

## 로컬 실행

필요 도구: [mise](https://mise.jdx.dev) (Node·pnpm 버전 관리).

```bash
mise install            # mise.toml의 node 24.18.1, pnpm 10.34.6 설치
node -v                 # v24.18.1 확인 — 다른 Node가 PATH 앞에 있으면 mise 버전이 가려진다
pnpm install
cp apps/web/.env.example apps/web/.env.local   # OPENAI_API_KEY 채우기 (AI 편집용)
pnpm dev                # http://localhost:3000
```

AI 편집: 키는 서버에서만 읽는다(`apps/web/src/app/api/ai/route.ts`). 개발 서버는 **가짜 응답 모드**로 시작한다 — 왼쪽 위 버튼으로 실제 AI와 바꿀 수 있고, 배포본에서는 주소에 `?debug=1`을 붙였을 때만 그 버튼이 보인다. 키가 없어도 가짜 응답으로 전체 흐름을 볼 수 있다.

배포본과 같은 결과(실제 AI가 기본, 디버깅 버튼 숨김)는 프로덕션 빌드로 실행한다. `OPENAI_API_KEY`가 필요하다.

```bash
pnpm build
pnpm start              # http://localhost:3000
```

공동 편집 확인: 같은 브라우저에서 같은 주소를 탭 여러 개로 연다. `localhost`와 `127.0.0.1`은 서로 다른 origin이라 동기화되지 않는다.

| 상태 소유권 3분할 (2절) | 공유+영속 = `Y.Doc`, 공유+일시 = awareness, 탭 로컬 = Zustand. 셀 데이터의 진실 공급원을 하나로 두어 탭 간 불일치가 생길 자리를 없앤다 | 셀 데이터를 Zustand에도 복사 — 동기화 코드가 불일치의 원천이 된다 |
| 셀마다 칸별 공유 맵 (8절) | 값과 굵게를 두 사람이 같은 칸에 동시에 바꿔도 둘 다 남는다 | 셀 하나를 통째 값으로 저장 — 나중 쓴 쪽이 다른 쪽을 지운다 |
| 도메인 로직을 `@sheet/core`로 분리 (1절) | 조용히 틀리기 쉬운 로직(좌표, undo 범위, AI 제안 판정·범위 검증)이 React·브라우저 없이 단위 테스트된다. 네트워크 확장 때 바뀌지 않는 부분이 패키지로 보인다 | 앱 안의 폴더 — 경계가 관례에만 의존 |
| 엑셀 조작 관례 (7절) | 사용자가 이미 아는 표 도구. 준비·입력·편집 모드, 셀 위 상시 입력칸(한글 첫 글자 유실 방지), 엑셀·구글 시트와 서식까지 오가는 복사·붙여넣기 | 독자적 조작 — 배울 것이 생긴다 |
| AI는 OpenAI 직접 연결, 셀 단위 스트리밍 (13절) | 한도를 OpenAI Console 한 곳에서 건다(선불 소액, 자동 충전 끔, 권한 제한 키). 완성된 셀만 한 칸씩 도착해 반쯤 써진 값이 보이지 않는다. 모델은 허용 목록 3개 — 공개 링크에서 비싼 모델을 임의로 부르지 못하게 | Vercel AI Gateway·OpenRouter — 이 규모에서 이점이 없고 경로가 하나 늘어난다 |
| AI 제안은 내 탭의 초안, 전체를 한 번에 적용 (13절) | 확정되지 않은 값이 시트와 다른 탭에 섞이지 않는다. 적용은 transaction 하나라 실행 취소 한 번으로 되돌린다 | 셀별 수락·거절 — 결정하는 곳이 둘이 되어 처음 보는 사용자에게 복잡했다(넣었다가 걷어냄) |
| 가짜 응답 모드 (13절) | 자동 테스트가 크레딧 없이 매번 같은 결과로 스트리밍·중지·실패를 시험한다 | 실제 API로 테스트 — 비용과 결과 흔들림 |
| 검증: core 단위 테스트 + 여러 탭 E2E (`.codex/skills/test-policy/SKILL.md`) | 탭 간 동기화·키보드·클립보드는 실제 브라우저에서만 드러난다. Playwright의 한 컨텍스트 안 여러 페이지가 "같은 브라우저의 탭"이다 | 컴포넌트 단위 테스트 — 탭 간 결함을 못 잡는다 |

기능 범위: 명세의 "적은 기능을 완성도 있게"에 따라 수식 계산, 행·열 삽입·크기 조절, 여러 시트, 셀 병합은 넣지 않았다. 시트는 100행 × 26열 고정이다(9절).

## 네트워크 기반 동기화로 확장한다면

바뀌지 않는 것: 문서 모델(`Y.Doc`의 셀 스키마), `@sheet/core` 전체, 실행 취소(내 origin만 추적), 화면. Yjs update와 awareness는 전송 수단과 무관한 바이너리라, 지금 BroadcastChannel로 보내는 메시지를 그대로 네트워크로 보내면 된다.

바뀌어야 하는 것:

1. **전송 계층** — `apps/web/src/collab/broadcastProvider.ts`를 WebSocket 연결(y-websocket 또는 Hocuspocus 서버)로 바꾼다. 지금의 메시지 세 종류(합류 인사 = state vector 교환, 문서 update, awareness update)가 Yjs sync 프로토콜의 step 1·2·update와 같다. 이미 있는 "다시 보이면 맞추기"(합류 인사 재전송)가 재연결 후 동기화 자리다. 연결이 끊긴 동안의 편집은 IndexedDB에 남고 다시 연결되면 CRDT가 병합한다.
2. **진실 공급원** — 지금은 각 브라우저의 IndexedDB가 저장소다. 서버가 문서 update를 DB(Postgres·S3 등)에 쌓고 주기적으로 스냅샷으로 합친다. IndexedDB는 오프라인·빠른 첫 화면을 위한 캐시로 남는다.
3. **문서 식별과 권한** — 지금은 origin당 시트 하나다(`sheet:default`). URL에 문서 ID를 두고(`/s/:id`) 서버가 방(room) 단위로 연결을 나눈다. 같은 origin의 탭은 서로 믿지만 네트워크에서는 아니므로, 서버가 연결마다 인증하고 읽기·쓰기 권한을 확인하며 update 크기를 제한한다.
4. **참여자 정체성** — 지금은 탭 = 참여자이고 이름은 탭마다 직접 정한다. 계정이 생기면 이름·색은 계정에서 오고, 한 사람이 여러 탭·기기로 들어오는 경우를 사용자 단위로 묶어 보여 준다. 탭 종료 정리(C6)는 `pagehide` 방송 대신 서버가 소켓 종료를 보고 그 참여자의 awareness를 지워 더 확실해진다.
5. **지연을 전제로 한 표시** — 네트워크 지연이 생기면 다른 사람의 커서·편집이 늦게 보이고, AI 제안의 "원래 값이 바뀜" 판정(X1)도 내 탭에 도착한 값 기준이 된다. 적용 직전에 서버 기준 값으로 한 번 더 확인하거나, 적용 후 도착한 원격 변경은 CRDT 병합 결과를 그대로 보여 준다. 겹침 경고(X3)는 awareness로 그대로 동작한다.
6. **AI 호출 제한** — 지금은 공개 링크의 남용을 요청 크기·출력 길이 상한·선불 한도로만 막는다. 계정이 생기면 사용자·문서 단위 호출 제한을 서버에 둔다.

## 공동 편집과 AI가 만나는 지점: 결정과 이유

원칙 하나로 정했다: **사람에게 알리고, 사람의 최신 편집을 지킨다.** AI는 보조 도구이고, AI가 결과를 만드는 사이 사람이 직접 바꾼 값이 더 최신의 판단이다. 상세 근거와 검토한 대안은 `DESIGN.md` 13·15절.

**AI가 결과를 만드는 동안 다른 참여자가 대상 셀을 수정하거나 삭제하면?**
결과를 버리지 않고, 그 칸만 "원래 값이 바뀜"(빨간 테두리·!)으로 표시한다. 적용 버튼은 [바뀐 n칸 빼고 적용]이 되어 그 칸을 건너뛰고, 나머지만 반영한다. "원래 값"은 요청을 보낸 순간의 값이다 — AI는 그 값을 보고 계산했으므로, 요청 뒤에 바뀐 칸에 AI 값을 덮으면 다른 사람의 편집을 지우거나 낡은 값으로 계산한 결과가 들어간다. 모든 칸이 바뀌었으면 적용 버튼을 잠그고 다시 요청하게 한다.
- 고르지 않은 안: 확인 후 덮어쓰기(남의 최신 편집을 지울 수 있다), 결과 전체 무효화(한 칸 때문에 전부를 잃는다).

**한 사람이 AI 결과를 검토하는 동안 다른 참여자에게는 무엇이 보여야 하나?**
누가 어느 범위를 AI로 만들거나 검토 중인지만 보인다 — 요청한 사람 색의 점선 범위, "서연 · AI 검토 중" 이름표, 참여자 목록의 상태. 제안 값은 보이지 않는다. 아직 적용 여부가 정해지지 않은 값이 다른 사람 화면에 보이면 확정된 값으로 오해할 수 있기 때문이다. 제안은 요청한 사람 탭의 초안(새로고침해도 남고 탭을 닫으면 사라짐)이고, 시트에는 적용된 값만 들어간다. 다른 참여자는 그 범위를 계속 편집할 수 있고, 그 편집은 위의 규칙으로 보호된다.

**두 사람이 겹치는 범위에 동시에 AI 편집을 요청하면?**
막지 않고 알린다. 보내기 전에 내 대상이 다른 사람의 AI 작업 범위와 겹치면 "서연님이 A2:A3 범위를 AI로 검토하는 중이에요. 겹치는 칸은 먼저 적용한 쪽이 반영돼요."를 보인다. 둘 다 진행할 수 있고, 먼저 적용한 결과는 나중 사람에게 "원래 값이 바뀜"이 되어 건너뛰어진다 — 충돌 처리는 첫 번째 규칙 한 곳에 모인다.
- 고르지 않은 안: 선점 잠금. 탭끼리 주고받는 상태로는 같은 순간에 보낸 두 요청을 막을 수 없고, 탭이 죽으면 잠금이 최대 30초 남으며, 누군가 시트 전체로 요청하면 모두가 막힌다. 불완전한 잠금은 "막힌 줄 알았는데 겹친" 더 헷갈리는 상황을 만든다.
